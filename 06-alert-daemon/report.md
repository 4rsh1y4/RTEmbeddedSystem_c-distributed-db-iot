## 1. معماری کلی سیستم و اجزای اصلی
طراحی این ماژول بر پایه معماری API Gateway صورت گرفته است. نود Master به عنوان نقطه ورود مرکزی عمل کرده و درخواست‌های مربوط به تاریخچه سنسورها را پردازش می‌کند. 
اجزای اصلی درگیر در این تراکنش عبارتند از:
* کلاینت متقاضی: ارسال‌کننده درخواست HTTP GET.
* وب‌سرور ناهمگام: مدیریت رویدادهای شبکه و اتصالات HTTP بدون مسدود کردن ترد اصلی.
* موتور پایگاه داده: سیستم ذخیره‌سازی محلی برای نگهداری ماندگار سری‌های زمانی سنسورها.

## 2. ارتباط بین اجزا و مسیر درخواست و پاسخ
ارتباطات در این ماژول به صورت همگام در لایه پایگاه داده و ناهمگام در لایه شبکه پیاده‌سازی شده است. مسیر جریان داده به این شکل است:

1. کلاینت یک درخواست GET به مسیر /api/logs همراه با پارامترهای نام، شناسه و تاریخ ارسال می‌کند.
2. کنترلر سیستم درخواست را دریافت کرده و پارامترها را استخراج و اعتبارسنجی می‌کند.
3. یک نشست موقت با دیتابیس SQLite باز می‌شود.
4. کوئری SQL برای استخراج لاگ‌های سنسور در تاریخ مشخص اجرا می‌شود.
5. داده‌های خام دیتابیس، سطر به سطر خوانده شده و به فرمت استاندارد JSON تبدیل می‌شوند.
6. اتصال دیتابیس بسته شده و پاسخ از طریق هدر HTTP (با کد 200 یا 404) به کلاینت بازمی‌گردد.

## 3. دیاگرام جریان داده
در این بخش از فلوچارت جریان داده (Data Flowchart) برای نمایش مسیر خطی درخواست تا پاسخ استفاده شده است:

```mermaid
flowchart TD
    Client([HTTP Client])
    MasterIn[Master Node<br>دریافت و اعتبارسنجی]
    DB[(SQLite Database)]
    MasterOut[Master Node<br>تبدیل به JSON]

    Client -- "۱. درخواست GET /api/logs" --> MasterIn
    MasterIn -- "۲. اجرای کوئری SELECT" --> DB
    DB -- "۳. بازگرداندن رکوردها" --> MasterOut
    MasterOut -- "۴. ارسال پاسخ نهایی" --> Client
