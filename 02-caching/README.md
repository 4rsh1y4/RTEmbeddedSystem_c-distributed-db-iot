## ۱. نیازمندی‌ها و نحوه نصب Memcached
برای اجرای این پروژه، علاوه بر کامپایلر C++ و SQLite3، به سرویس Memcached و کتابخانه‌ی توسعه‌ی آن در C نیاز دارید.

برای نصب پیش‌نیازها در توزیع‌های مبتنی بر دبیان/اوبونتو، دستور زیر را اجرا کنید:
```bash
sudo apt update
sudo apt install -y memcached libmemcached-dev sqlite3 libsqlite3-dev build-essential curl nc
```

## ۲. نحوه اجرای سرویس Memcached
سرویس Memcached پس از نصب معمولاً به صورت خودکار اجرا می‌شود. با این حال، می‌توانید وضعیت آن را بررسی کرده یا آن را به صورت دستی مدیریت کنید:

**بررسی Status:**
```bash
sudo systemctl status memcached
```

**ری استارت سرویس:**
```bash
sudo systemctl restart memcached
```
*نکته: سرویس Memcached به صورت پیش‌فرض روی پورت `11211` لوکال‌هاست (`127.0.0.1`) گوش می‌دهد.*

## ۳. نحوه کامپایل برنامه‌ها
در پوشه‌های `master` و `slave` فایل‌های `Makefile` قرار داده شده‌اند که وظیفه‌ی لینک کردن کتابخانه‌های Mongoose، SQLite (`-lsqlite3`) و Memcached (`-lmemcached`) را بر عهده دارند.

برای کامپایل دستی هر نود، کافیست وارد پوشه مربوطه شده و دستور `make` را اجرا کنید:
```bash
cd 02/master
make

cd ../slave
make
```
*البته با اجرای اسکریپت راه‌اندازی (بخش بعد)، عملیات کامپایل به صورت خودکار انجام خواهد شد.*

## ۴. نحوه اجرای خودکار و هوشمند سیستم (Auto-Detection)
برای راحتی کار و جلوگیری از اجرای دستی دستورات در ماشین‌های مختلف، یک اسکریپت بش هوشمند (`build_and_run.sh`) در پوشه `scripts` توسعه داده شده است. این اسکریپت نقش هر ماشین مجازی در کلاستر را به صورت خودکار تشخیص می‌دهد.

برای راه‌اندازی سیستم، کافیست در **تمام ماشین‌ها (چه Master و چه Slaveها)** دستورات زیر را اجرا کنید:

```bash
cd 02/scripts
chmod +x *.sh
./build_and_run.sh
```

**کارهایی که این اسکریپت به صورت هوشمند روی هر ماشین انجام می‌دهد:**

* 1. **تشخیص نقش نود (Auto-detect):** اسکریپت، IP ماشین لوکال را خوانده و با فایل `config.txt` تطبیق می‌دهد تا تشخیص دهد ماشین فعلی master, slave1 یا slave2 است.

* 2. **راه‌اندازی پایگاه داده (SQLite):** اسکریپتِ مقداردهی اولیه مخصوص به همان نود (مانند `master_init_db.sh` یا `slave1_init_db.sh`) را اجرا می‌کند تا دیتابیس لوکال آماده شود.
* 3. **راه‌اندازی لایه کش (Memcached):** اسکریپت `memcached_init.sh` را برای بررسی و فعال‌سازی سرویس کش در همان ماشین اجرا می‌کند.
* 4. **کامپایل خودکار:** وارد پوشه مربوطه (master یا slave) شده، فایل‌های کامپایل قبلی را پاک کرده (`make clean`) و کدها را مجدداً توسط `Makefile` کامپایل می‌کند.
* 5. **اجرای سرویس:** در نهایت، فایل اجرایی نود را با آرگومان‌های اختصاصی خودش (مثل IP، پورت و نام دیتابیس) اجرا می‌کند.

## ۵. نحوه ارسال درخواست به سیستم
پس از اجرای کامل شبکه، نود Master به عنوان API Gateway عمل کرده و درخواست‌ها را دریافت می‌کند. اگر داده مربوط به سنسورهای خودش باشد پاسخ می‌دهد، و در غیر این صورت درخواست را به صورت Async به Slave مربوطه مسیردهی (Route) می‌کند.

برای ارسال درخواست و خواندن دیتای یک سنسور (مثلاً سنسور 101 یا 201)، از دستور `curl` استفاده کنید:
```bash
curl "http://<MASTER_IP>:<MASTER_PORT>/api/sensor?id=201"
```
**نمونه خروجی سیستم:**
```json
{"sensor_name": "Temperature_LivingRoom", "value": 24.5, "unit": "Celsius", "recorded_at": "2023-10-27 10:00:00", "response_time_ms": 0.123}
```

## ۶. نحوه اجرای اسکریپت تست سرعت (Benchmark)
برای مقایسه عملکرد سیستم در حالتِ بدون کش (Cache Miss) و با کش (Cache Hit)، اسکریپت بنچمارک توسعه داده شده است. این اسکریپت آی‌پی و پورت مستر را از فایل کانفیگ خوانده و تست را در دو دور اجرا می‌کند.

برای اجرای تست:
```bash
cd 02/scripts
chmod +x benchmark_read.sh
./benchmark_read.sh ../master/config.txt
```

### تحلیل مختصر نتیجه تست:
*   **دور اول (Round 1):** کش Memcached پیش از اجرای تست خالی (Flush) می‌شود. در این دور، سیستم با **Cache Miss** مواجه شده و داده‌ها از SQLite خوانده می‌شوند. زمان پاسخ‌دهی به دلیل درگیری دیسک و تاخیر شبکه (Network Routing) بیشتر است.
*   **دور دوم (Round 2):** داده‌ها در حافظه RAM (Memcached) ذخیره شده‌اند (**Cache Hit**). سرعت خواندن سنسورهای محلی به شدت افت کرده (حدود ۰.۱ میلی‌ثانیه). در مورد سنسورهای توزیع‌شده (Slaves)، با وجود اینکه داده‌ها در کشِ خودِ اسلیو با بالاترین سرعت خوانده می‌شوند، زمان نهایی شامل تاخیر طبیعی رفت‌وبرگشت در بستر شبکه (Network Jitter) می‌باشد که نشان‌دهنده یک معماری کاملاً استاندارد و غیرمتمرکز است.
